# ServeAI disposable browser E2E suite

This is a **19-test subset** of [Issue #17](https://github.com/FahadIbrahim93/Htl-ServeAI/issues/17). The separate env-unset guest/login smoke suite is in PR #38. This branch also verifies expired-session refresh on the callback redirect before onboarding and dashboard navigation. These PRs require integration and review before claiming the full #17 acceptance gate. The tests include friendly unknown-account/wrong-password errors, missing/invalid callback feedback, sign-out cookie removal, tampered-session denial on both protected routes, duplicate slugs and cross-tenant PostgREST access checked using a token read from the browser session. Do not claim the issue is complete until all 15 acceptance scenarios pass (test count alone does not prove coverage).

The suite is **hard-gated** to `E2E_DISPOSABLE_ONLY=1` and local HTTP origins; no hosted Supabase project, real customers or production credentials may be used.

Local setup: in a disposable checkout only, set `[auth].jwt_expiry = 120` and `[auth.email].enable_confirmations = false` in `supabase/config.toml`, then start `supabase start`, run `npm ci` at the root, and `npm ci --prefix tests/e2e`. Configure the local `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, run `npm run build && npm run start` in one terminal, then `E2E_DISPOSABLE_ONLY=1 E2E_LOCAL_DB_CONTAINER=supabase_db_htl-serveai npm run test:e2e --prefix tests/e2e`.

CI uses a disposable Supabase project with email confirmations disabled in its temporary local config. The workflow records cookie **flags only**, never cookie values, JWTs or service-role keys. Playwright traces are disabled because they capture passwords, Authorization headers and session cookies. HTML reports and screenshots are uploaded only upon failure, with short retention; treat those artifacts as sensitive too.

The quota test uses `docker exec` to shift only the signed-in disposable user's `tenant.created` audit timestamps beyond the 60-second cooldown. It does not change the production RPC or expose a test helper through the API. Use a fresh local stack with project ID `htl-serveai`, never a shared development database.

Lifecycle tests wait through real 120-second JWT expiry windows. After browser signup they close the original page and use a context with JavaScript disabled to prove server-side refresh, without a background browser refresh masking failures. The suite takes roughly six extra minutes. A separate case revokes the real refresh session through local Auth before checking expired-cookie denial. Session/token comparisons assert booleans to avoid printing credentials.

Public pages have a separate database-free smoke suite. With both Supabase public environment variables unset, build the app, then run `npm exec --prefix tests/e2e -- playwright test --config tests/e2e/public.config.mjs` from the repository root. It starts its own production server and checks `/` and `/login`; the `Public pages without Supabase` workflow runs the same check.
